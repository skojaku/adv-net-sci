{\LARGE\bfseries Module 5 --- Pitch your community partition}

\vspace{0.1em}
\rule{\textwidth}{0.8pt}

\textbf{What this is.} A community analysis of our own seating. Each person in this room is
a node, and each is joined to their \texttt{K} nearest people. That is a network of about
15 nodes. Nobody knows which communities it ``really'' has: there is no answer key. Your
group is given one definition of a community. Using it, you make a partition of the nodes
and, in \textbf{three minutes}, say why it is the one to use.

\medskip
\textbf{Rules.}
\begin{enumerate}[label=\arabic*.]
\item Argue only from your own definition of a community. It is the only thing you have.
\item Back your pitch with numbers you computed or ran yourself. A plausible partition is not enough.
\item \texttt{K} (how many nearest people each person is joined to) is a variable in the notebook. Changing it changes the network, and every answer. Say which \texttt{K} you used.
\item When you are asked a question, answer from your own definition. Before you call another group's partition wrong, say whose definition you are using.
\end{enumerate}

\textbf{Plan.}\par\vspace{-0.2em}
\begin{tabular}{@{}>{\bfseries}r p{1.7cm} p{12.6cm}@{}}
10 min & Prepare &
Make your partition. Then write four sentences: (a) your definition of a community;
(b) who your partition puts together, and who it separates from whom; (c) one number
that supports it; (d) one thing it cannot do. The other groups will find (d) if you do not. \\
12 min & Pitch &
Three minutes per group, in the order 1, 2, 3, 4. Everyone else writes down one question
for the group that is speaking. \\
5 min & Questions & Each group asks its question. The speaking group answers. \\
3 min & Discuss & Which partition is correct? What would you need to know to say? \\
\end{tabular}

\medskip
\textbf{Questions you could ask.}
\begin{itemize}
\item What did you decide before you started (\texttt{K}, the number of groups, $k$, $\rho$, the objective)? What changes if you decide differently?
\item Pick a node that sits between two groups. Why is it with the group it is in?
\item Does your method need to be told how many groups there are?
\item Which of the four would you use to form discussion groups for this class? Does the answer depend on what the groups are for?
\end{itemize}

\begin{groupbox}{2}{Cut (by eye)}
A community is one side of a split with few edges between the sides, relative to size.
Make \textbf{exactly two groups}, numbered 0 and 1, so that both of these are as small as possible:
\[
\text{Ratio cut}=\frac{\ell}{|V_0|}+\frac{\ell}{|V_1|},\qquad
\text{Normalized cut}=\frac{\ell}{\text{vol}(V_0)}+\frac{\ell}{\text{vol}(V_1)}.
\]
$\ell$ is the number of edges between the two groups; $\text{vol}(V_c)$ is the sum of the
degrees of the members of group $c$. From the matrix \texttt{show} prints: $|V_c|$ is the size,
$\ell$ is the off-diagonal entry, and $\text{vol}(V_c)=2\times(\text{diagonal entry})+\ell$.
\textbf{A plausible split is not enough.} Compute both values by hand for at least three
candidate splits and keep the smallest. In your pitch, give the smallest values you found and
what you tried. Do the two objectives pick the same split?

\begin{groupbox}{3}{Chance: modularity (igraph)}
A community is a set with more edges inside than a random network with the same degrees would
put there. Maximize $Q=\frac{1}{2m}\sum_{ij}\bigl[A_{ij}-\frac{k_ik_j}{2m}\bigr]\delta(c_i,c_j)$.
Type each box into the empty cell of your section, by hand. The network is \texttt{graph}.
\begin{lstlisting}
labels = graph.community_leiden(
    objective_function="modularity",
    n_iterations=-1).membership
show(labels)
print(graph.modularity(labels))
\end{lstlisting}
Leiden finds the grouping with the highest $Q$. Louvain starts from a random node order, so another seed can change the answer:
\begin{lstlisting}
import random
random.seed(1)
part = graph.community_multilevel()
labels = part.membership
\end{lstlisting}
\end{groupbox}
\end{minipage}\hfill

\begin{groupbox}{4}{Pattern: block model (graph-tool)}
A community is a set of nodes that connect to every group in the same way. The grouping that
gives the shortest description of the network wins. The first run installs graph-tool (1--3
minutes; it does not run on Windows, so use Colab there). In \texttt{fit}, \texttt{g} is the
network and \texttt{gt} is graph-tool.
\begin{lstlisting}
def fit(g):
    state = gt.minimize_blockmodel_dl(g)
    return state.get_blocks().a.tolist()

labels = graph_tool(fit)
show(labels)
\end{lstlisting}
Replace the \texttt{state = \ldots} line, one at a time, and compare. The first lets every node have its own degree; the second forces 2 groups.
\begin{lstlisting}
state = gt.minimize_blockmodel_dl(
    g, state_args=dict(deg_corr=True))
state = gt.minimize_blockmodel_dl(
    g, multilevel_mcmc_args=dict(B_min=2, B_max=2))
\end{lstlisting}
\end{groupbox}
